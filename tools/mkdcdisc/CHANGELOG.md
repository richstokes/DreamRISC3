# mkdcdisc Changelog

| Date                   | Author(s)                   | Changes                   |
|:-----------------------|:----------------------------|:--------------------------|
| 2026-08-18 | Mickaël Cardoso | Adds `--duplicates-once` (off by default), matching mkisofs feature: byte-identical files share one extent instead of each getting a copy. Matched by content, never by device/inode numbers, which Windows does not supply. Files are grouped by size, digested over their first 64 KiB and then whole, and compared byte by byte before any merge, so no digest collision can share an extent between two different files. The boot binary and the three fillers are never shared. A set carrying `-S/--sort-file` weights takes the highest of them, as mkisofs does, and the files placed below it are named in a warning, which mkisofs does not do.

Duplicates are found by grouping on size, then digesting only ambiguous groups, then byte-comparing before merging, so digest collisions can't wrongly merge files. The alphabetically-first path wins, keeping `SOURCE_DATE_EPOCH` builds reproducible.

Never shared: the boot binary (pinned to a fixed position), padding/spacer/filler files (already identical to each other by construction), and `-S/--sort-file`-weighted files (can't share one weight). For `-F gdi`, only the high-density area is affected. |
| 2026-08-17 | Mickaël Cardoso | mkdcdisc now refuses to overwrite existing output files by default, since it previously silently truncated whatever `-o` named; including a `.gdi` dropping track files into a directory another descriptor already used, corrupting both. It now checks the *entire* set of files a build will produce (not just the named output) before writing anything, naming every conflict and exiting with code 4. `--allow-overwrite` restores the old silent-overwrite behavior, now logged instead of silent. |
| 2026-08-17 | Mickaël Cardoso | Adds pre-write boot validation for `-t/--external-data-track` discs (and mkdcdisc's own output across all formats): boot header integrity, SEGA license screen byte-match, boot file present at root, and MSINFO/session-start correctness. License-screen mismatch is a hard error (hardware compares byte-for-byte); MSINFO mismatch only warns, being a modeled estimate. Can now refuse `-t` builds earlier releases silently accepted and never booted; `--disable-bootstrap-checks` downgrades everything to warnings. Only the actually-booted volume is checked (session 2 under merged-data, high-density under `-F gdi`). Also fixes `--boot-filename` case handling: ISO9660 has no lowercase, so libisofs uppercases the filesystem tree while mkdcdisc wrote the header verbatim, e.g. a header naming `game.bin` over a tree only containing `GAME.BIN`. The IP.BIN field is now uppercased to match; the staged file, Joliet, and Rock Ridge keep the original case, since that's what KallistiOS resolves at runtime. `-F gdi`'s boot-binary placement lookup now goes through `boot_filename()` instead of the header field, to match. `-p/--bootstrap` headers stay exempt, used verbatim by contract. |
| 2026-08-16 | Mickaël Cardoso | Fill in what `--help` still left to be found out elsewhere. The opening description becomes two paragraphs: what the tool is and which image it builds, then what the result is for — an emulator, or real hardware through a burned CD-R or an ODE — which the option list never says and which is the whole point of running it. Every default that was implied is now written down (`-v` `1`, `--color` `auto`, `-F` `cdi`), and each option value is quoted the way the rest of the list already quoted them, so a value to type and a word in a sentence no longer look alike. Three facts are added rather than reworded: the license screen the built-in bootstrap carries is quoted, so what a disc says by default is visible before it is burned rather than only in [cli-reference.md](docs/cli-reference.md); "Data Track Contents" says that `-t/--external-data-track` disables the whole group, which until now was stated on `-t` alone and nowhere the reader of those options would see it; and `-t` says it is given twice in `merged-data`, which only `-L`'s "requires two -t ISOs" hinted at. |
| 2026-08-15 | Mickaël Cardoso | Record what actually decides whether a `--gdi-truncate` image boots, which is not its size. Sega's rules require a GD's high-density area to hold at least 30 minutes, so a shrink mode floored there looked worth adding alongside the existing one. It is not: nullDC refuses a truncated image at 30 minutes and at 89 minutes exactly as it refuses one at 4 seconds, and boots only a full-size build. The criterion is that the area reaches LBA 549150, so no floor short of the full size helps anything that reads the image, and the 30-minute minimum is a constraint on pressing a disc rather than on reading one. [gd-image.md](docs/gd-image.md) carries the measurements and `gd_track_plan.hpp` the reasoning, so the option does not get proposed again from the same reading of the rules. A `--gdi-truncate` build now also ends by saying what it produced: a warning naming the LBA its high-density area stopped at, that the image is not standard and may not boot, and what is known to refuse one. Worded cautiously on purpose — two emulators have been tried and no real hardware — and silenced by `-q` like any other advisory. |
| 2026-08-15 | Mickaël Cardoso | Refuse an audio track count the disc cannot carry, instead of finding out too late or not at all. With `-F gdi` the limit is 95: Sega's rules for a GD allow that many audio tracks in the high-density area followed by another Mode 1 track, and the structure gives the same figure — the area spans tracks 3 to 99, with a data track at each end of the audio — which is why the `TOC1` table mkdcdisc writes holds exactly 97 entries. Past it that array simply stopped being filled while the `last` field it publishes kept counting, so the image announced tracks that had no entry, with nothing in the output to say so. For a MIL-CD the limit is 98, from the Red Book ceiling of 99 tracks that every one of these formats inherits, less the data track; past it the writers already refused, but only once the whole disc had been built, as a bare "unable to build the disc image". Both counts are answerable from the options alone, so both are now refused as usage errors before a single audio file is opened. The ceiling itself becomes `CD_MAX_TRACKS`, which the four writers use in place of the literal each carried. |
| 2026-08-15 | Mickaël Cardoso | Stop putting the main executable on the disc twice. The file given to `-e`/`-b`/`-B` is already there, converted, as `1ST_READ.BIN`; when `-d`, `-D` or `-f` also swept it up it was copied a second time in its source form, silently — for `-e game.elf -D build/`, the size of the boot payload over again for nothing. It is now left out wherever it is reached from, with a warning naming the file, the option that reached it and the bytes saved, and matched by identity rather than by name, so a tree holding `game.elf` is caught like one holding `1ST_READ.BIN`. `-f` is treated the same: naming a file explicitly does not make a second copy of it useful. The only pre-existing guard, `-D`'s skip of an entry called `1ST_READ.BIN`, was a `-v 2` aside and is now a warning too; the same guard reaches `-d` and `-f`, the latter of which used to end the run on a raw `filesystem error: cannot copy: File exists` from the collision. `--gdi-lda-*` is deliberately untouched: the low-density area never holds the boot binary, and putting an executable in the part of the disc a PC reads can be the point. |
| 2026-08-14 | Mickaël Cardoso | Rename `-n/--name` to `-n/--title`, after the IP.BIN header field it fills, which is the software title. `--name` said neither what it names nor which of three it was: `-V/--volume-label` is a name too, `--boot-filename` is a third, and this one is the only one the console itself displays. The short flag is unchanged and `--name` stays accepted as a deprecated spelling. Nothing else moves — the value still reaches the IP.BIN title, the ISO9660 volume label it is the default for, the PVD identifiers and the generated `COPYRIGH.TXT`. |
| 2026-08-14 | Mickaël Cardoso | Rename `-b/--main-bin-unscrambled` and `-B/--main-bin-scrambled` to `--main-binary-unscrambled` and `--main-binary-scrambled`: the group already spells the word out in its own description and in `-e/--main-elf`'s neighbours, so the abbreviation was the odd one out. `-B`'s description drops "already" — the format is scrambled either way, and whether it got that way before mkdcdisc saw it is what the option name says. The short flags are unchanged, and both previous long names stay accepted as deprecated spellings: these two options have now been renamed twice, first into the group prefix and now out of the abbreviation, so they are the first to carry two superseded names each — the alias list already allowed it, nothing had needed it yet. |
| 2026-08-14 | Mickaël Cardoso | Replace `-L/--data-data-layout` and `-K/--merged-data-layout` with one `-L/--disc-layout` taking `audio-data` (the default), `data-data` or `merged-data`. The three layouts are mutually exclusive, so two flags could also say "both" — a state that is not a disc, and that each of the three places reading them had to refuse by hand, in messages that then had to name the other flag. One value makes it unrepresentable: those checks are gone rather than moved, the four near-identical "no audio session for CDDA tracks" refusals collapse into one, and `-F gdi` rejects the whole option through the same option-table field every other disc-type restriction uses. It also gives the default a name, which a script generating an invocation could not write down before. The old spellings are not accepted, not even deprecated: `-L` now takes a value, so an invocation written against them fails outright — every option value here follows its flag, leaving no way for the old form to be misread as something buildable. |
| 2026-08-11 | Mickaël Cardoso | Fixes GD-DA discs producing sub-Red-Book-minimum data tracks (e.g. 173/232 sectors). `MIN_HD_SECTORS` only floored the whole high-density zone, not each of the 2 data tracks it gets split into once audio is present. The fix reserves `MIN_SPLIT_SIDE_SECTORS` of hidden filler on both sides of the audio split. Only `-c/--cdda-track` builds are affected. `bootable_disc` now asserts the floor directly, since track length isn't recorded in either manifest. |
| 2026-08-11 | Mickaël Cardoso | Add the pipeline for building discs from real Dreamcast executables, and pin what ends up on them as `tests/fixtures/bootable-disc-manifest.txt`. Everything else end-to-end builds from `tests/fixtures/dummy.bin`, 4096 identical bytes, through which two things cannot be seen: `-e/--main-elf` never converts an ELF, since a non-ELF makes every use of it an error path; and scrambling a file of one repeated byte returns that same file, so the scrambler has never really run. The new corpus builds thirteen images from a KallistiOS ELF (`-e`) and a Katana binary supplied both unscrambled (`-b`) and already scrambled (`-B`, produced by the test itself rather than a third committed file), across every format and every layout including GD-DA, whose volume is split around the audio so the boot binary sits in a closing track past its own descriptors. Each image is read back through a container parser that shares no arithmetic with the writers, the boot binary unscrambled and required to be exactly what went in, and one payload must land identically on every disc it is written to. The executables themselves are committed prebuilt under `tests/payloads/` — no CI target has an SH-4 toolchain — and until they are there the test is not registered and `meson setup` says so. `meson compile -C builddir demo-discs` runs the same corpus and keeps the images, which the CI publishes for trying on a console. |
| 2026-08-10 | Mickaël Cardoso | Pin the table of contents the writers lay down, as `tests/fixtures/disc-manifest.txt`: sessions, tracks, modes, pregaps, the gaps between tracks and the run-out past each volume, for six layouts across all four output formats. The other end-to-end checks assert properties, which only catch what someone thought to assert; this one records the whole layout and requires it not to move. The images are read back by a parser (`tests/common/disc_read.h`) that shares no arithmetic with the writers, since a reader built on the writer's own layout code would confirm the writer including its mistakes. Unlike `iso-manifest.txt`, which pins what `libisofs` writes and therefore only runs against the vendored copy, this manifest holds nothing `libisofs` decides and runs on all four CI targets against the same committed file: a data track's length is never stated, only the distances mkdcdisc chooses around the filesystem, so a distribution shipping a different `libisofs` cannot move it. Regenerate after an intended layout change with `meson compile -C builddir regen-disc-manifest`. |

| 2026-08-08 | Mickaël Cardoso | Add `--gdi-disable-copyright`, `--gdi-disable-abstract` and `--gdi-disable-biblio`, a way out of the three low-density text files a GD-ROM build writes on its own. `-F gdi` generates `COPYRIGH.TXT`, `ABSTRACT.TXT` and `BIBLIOGR.TXT` from the disc metadata whether or not they were asked for, because every pressed disc carries all three, which is also why only that format needs the flags: a MIL-CD (`-F cdi`/`mds`/`nrg`) generates nothing and only ever carries the ones `--copyright`/`--abstract`/`--biblio` name, so there is nothing there to switch off. | 2026-08-07 | Mickaël Cardoso | Refresh the bundled IP.BIN templates, and add `--gdi-fpu-rounding` to pick which SH-4 `FPSCR` rounding mode the GD-ROM bootstrap leaves set: `nearest`, what every earlier release shipped and still the default, or `zero`. The two variants differ only in their second-stage bootstrap, so the choice reaches nothing else on the disc, and `-v 3` reports it. Stop bundling `IP0000.BIN` as a template of its own: the low-density boot image is the high-density header repeated over sixteen empty sectors, so it is built from whichever `IP.BIN` is in use, which also gives each rounding variant its matching low-density image for free. |
| 2026-08-07 | Mickaël Cardoso | Open a `-v 3` run with a build plan: one aligned block naming the disc type, image format and layout, the files that will be written, the volume label and boot filename, the executable and what happens to it, the whole IP.BIN metadata set, the disc contents and the layout-specific settings — before any of it is acted on.
